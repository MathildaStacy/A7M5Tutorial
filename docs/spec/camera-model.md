# 3D 相机模型规范

| 项 | 内容 |
|---|---|
| 对象 | Sony α7 V 机身（ILCE-7M5）+ FE 24-70mm F2.8 GM II（SEL2470GM2） |
| 要求 | **和真机一模一样**：外形、尺寸、每个按键的位置和刻字、材质、每个活动部件的转动方式都和实物一致 |
| 用途 | App 相机 Tab、课程演示、AI 教练对话里的 3D 卡片 |
| 读者 | 建模师（外包或自制）、Astra（集成）、PM 和用户（验收） |
| 日期 | 2026-11-24 |

HTML 原型里的程序化模型**只用来说明交互，不进 App**。正式模型到位之前，开发版可以用占位模型（见 §8）；**上线必须用按本文验收通过的模型**。

## 1. 模型从哪里来

| 部分 | 现状（2026-11-24 查询） | 做法 |
|---|---|---|
| 机身 | CGTrader、TurboSquid、Sketchfab 上都没有 α7 V 的模型。这台相机 2025 年 12 月才发布 | **找专业的硬表面产品建模师，照用户的实机建模** |
| 镜头 | CGTrader 上有一个 SEL2470GM2 的模型（作者 kalsary，Rhino 原生，面向渲染） | 可以买来当底子，由建模师重新拓扑、拆件、绑定；也可以和机身一起从头做。**购买前确认许可证允许把模型嵌入 App 发布** |

- **不用 Sony 的 CAD 数据**，也不从 Sony 官网的产品图里抠贴图。
- **参考资料**：
  - 用户实机的参考照片包（§2）。
  - 帮助指南里的部件名称图、规格页的外形尺寸。
  - 必要时用游标卡尺实测。
- **用户要做的决定**：建模由谁做（外包，还是自己用 Blender 做），以及预算。PM 建议外包，原因是「一模一样」需要专门做硬表面产品建模的经验，这不是开发的强项。

## 2. 参考照片包（用户提供，约 1 小时）

建模师手上没有这台相机，参考资料全靠这个照片包，所以质量决定了模型能有多像。

**拍摄条件**

- 用灰色或白色的纯色背景，光线均匀柔和，避免强烈反光。
- 用手机长焦端在 2 米左右拍，减少透视变形。画面里放一把钢尺。
- 开着 **0.5×** 等超广角镜头拍会严重变形，不要用。

**清单**

| 编号 | 内容 | 数量 |
|---|---|---|
| R1 | 机身（装好机身盖、不装镜头）：前、后、顶、底、左、右六个正视角 | 6 |
| R2 | 装上镜头，焦距 24 mm 和 70 mm 各拍一组：前、后、顶、左、右；记下两种焦距下镜筒的长度 | 10 |
| R3 | 45° 斜视角：左前上、右前上、左后上、右后上 | 4 |
| R4 | `controls.json` 里每个部件的特写，带尺子 | 约 36 |
| R5 | 所有刻字和标记的特写：按键上的字、模式转盘、下层转盘、镜头上的开关和刻度 | 若干 |
| R6 | 材质特写：握把的皮纹、拨盘的滚花、镜头上的橡胶环、金属卡口 | 若干 |
| R7 | 打开的状态：卡槽盖、电池仓盖、各个接口盖、翻开的显示屏（每个极限角度各一张）、取下的眼罩 | 若干 |
| R8 | 视频：每个拨盘慢慢转一整圈（用来数一圈有几格）；模式转盘把每一档都转一遍；对焦环、变焦环、光圈环各转一遍；显示屏翻转的全过程 | 若干 |
| R9 | 镜头取下后的机身卡口（装着机身盖拍，**不要让传感器长时间暴露**） | 1 |

**用卡尺量的数据**（有卡尺就量，没有就跳过）：各个按键的直径、各个拨盘的直径和厚度、凸出机身的高度。写进 `docs/reviews/assets/model-ref/measurements.md`。

照片放在 `docs/reviews/assets/model-ref/`，按编号命名，例如 `R4_btn_c1.jpg`。

## 4. 坐标、单位、层级

- **坐标和单位**：采用 glTF 2.0 约定，Y 轴朝上，相机正面（镜头方向）朝 +Z。单位是**米**，按真实尺寸建模。
- **原点**：影像传感器平面的中心，也就是机顶 ⊖ 标记对应的那个平面。这样最近对焦距离、景深这类从传感器平面量起的数据，可以直接在场景里演示。
- **层级：**

```
a7v (root)
├─ body
│  ├─ <controls.json 里的机身部件，节点名 = id>
│  ├─ dial_rear_r_lock        后拨盘 R 中央的锁定钮
│  ├─ mode_switch_lock        下层转盘的锁定释放按钮
│  ├─ lcd                     显示屏总成（铰链）
│  │  └─ lcd_screen           屏幕发光面，UV 铺满 0–1
│  ├─ evf
│  │  └─ eyecup               可取下
│  ├─ decal_brand             品牌标识（见 §6）
│  └─ body_static             其余不动的外壳
└─ lens（可以从机身上拆下）
   ├─ ring_zoom / ring_focus / ring_aperture / sw_* / btn_focus_hold …
   ├─ lens_barrel_inner       随变焦伸缩的内筒（按实物，见 R2）
   ├─ hood（可选，可拆）
   └─ lens_static
```

- `controls.json` 里的 36 个 id，**每个都必须是独立的节点**，节点名和 id 完全一致。
- 一个部件有好几块（比如拨盘和它的刻字）时，放在同名节点下面当子节点。
- 建模时发现实物上有、但 `controls.json` 里没有的活动部件，先按上面的规则命名，并告诉 PM，由 PM 补进 `controls.json`。

## 5. 活动部件的绑定（glTF `extras`）

每个活动部件节点的轴心要放在真实的转轴或滑动起点上，并且在节点的 `extras` 里写清楚怎么动。App 按这些数据播放动画，所以**不用在代码里写死角度**。

```jsonc
"extras": {
  "kind": "rotate",          // rotate 转动 | press 按压 | slide 滑动 | hinge 铰链 | tilt 摇杆 | static 不动
  "axis": [0, 1, 0],         // 局部坐标系下的单位向量
  "detent_deg": 15,          // rotate：每一格的角度，按实物数（R8）；无级转动的（如对焦环）写 null
  "travel_m": 0.0006,        // press 的按下深度、slide 的滑动距离；不适用写 null
  "range_deg": null,         // hinge，或者转动有极限时：[最小, 最大]
  "positions": { "AUTO": 0, "P": 30 }   // 有名字的档位 → 角度（度）或位移（米）；键名必须和 controls.json 的 positions 完全一致
}
```

**必须按实物测的数据**
- 模式转盘每一档的角度。
- 下层转盘三档的角度。
- 光圈环上从 F2.8 到 F22 每 1/3 档的角度，以及 A 档的位置。
- 变焦环从 24 转到 70 的总角度，标出 24、28、35、50、70 各刻度的位置，并给出对应的内筒伸出量。
- 显示屏的翻转方式和各个方向的极限角度。
- 各个盖子打开的角度。

## 6. 外观

| 项 | 要求 |
|---|---|
| 形状 | 倒角、分模线、螺丝、孔位、背带环、麦克风孔、扬声器孔、指示灯、热靴触点、卡口触点，实物上看得见的都要做 |
| 刻字 | 按键上的字（C1、MENU、AF-ON……），模式转盘、下层转盘、镜头开关的字，以及镜头上的焦距刻度，全部按实物的字体、位置和颜色做。在 App 里放到最大时，1080p 屏幕上也要清楚可读 |
| 材质 | PBR 金属粗糙度流程：baseColor、metallicRoughness（打包成 ORM）、normal。握把皮纹、拨盘滚花、橡胶环用法线贴图表现。对着 R6 照片调，粗糙度要分出层次：漆面、橡胶、金属不能是同一种「黑」 |
| 品牌标识 | SONY、α、G Master 等标识放在独立节点 `decal_brand` 里，可以单独隐藏。个人使用的构建显示；如果将来公开上架，就隐藏（PRD §12） |
| 屏幕内容 | 由 App 实时绘制，贴到 `lcd_screen` 上。版式参照帮助指南里的屏幕图标说明，自己画，**不用 Sony 的界面截图当贴图** |

## 7. 预算和验收

**资源预算**

| 项 | LOD0（相机 Tab） | LOD1（对话卡片） |
|---|---|---|
| 三角面（机身 + 镜头） | ≤ 200,000 | ≤ 60,000 |
| 贴图 | KTX2 压缩；单张 ≤ 2048×2048；总数 ≤ 10 张 | 共用 LOD0 的贴图，或缩到一半 |
| 文件大小 | ≤ 20 MB（meshopt 压缩） | ≤ 6 MB |

**每一轮验收看什么**（结果放进 `docs/reviews/model-v{n}/`）

1. **尺寸**：外形的宽、高、厚和规格页一致，误差 ≤ 0.5 mm。镜头的直径和长度和规格一致。
2. **位置**：用和 R1、R2 相同的视角渲染正交图，以 50% 透明度叠在照片上。每个部件中心的偏差 ≤ 1 mm。
3. **完整性**：对照 R1 到 R7 逐项打勾。实物上看得见的东西都在，`controls.json` 里的 36 个节点都在。
4. **刻字**：把 R5 的每张特写和 App 里同一角度的截图并排放，逐个核对。
5. **活动部件**：每个部件在 App 里的转动方向、格数和档位，都和 R8 的视频一致。
6. **材质**：在相同角度和类似的光线下，渲染图和 R3、R6 的照片并排对比。
7. **机器检查**：`node scripts/check-model.mjs` 没有错误（§9）。
8. **最终签字**：用户拿着真机，对照 App 里的模型确认「一模一样」。只有签字后才算通过。

## 8. 进度（和开发并行）

| 周 | 模型这条线 | 开发这条线 |
|---|---|---|
| 第 2 周 | 定下建模的人和预算；用户拍好参考照片包 | Astra 用原型的程序化模型导出一个**占位 GLB**，节点名和 `extras` 都按本文的格式来，App 从第一天起就加载 GLB |
| 第 3 周 | **白模 v1**：形状大致对，所有节点和 `extras` 都齐全 | 把白模接进 App，尽早验证节点和绑定的格式 |
| 第 5 周 | 形状定稿，按 §7 第 1–3 条验收 | T1.7 性能验证，用白模测 |
| 第 7 周 | 材质和刻字定稿，按 §7 第 4–6 条验收 | |
| 第 8 周 | LOD1、压缩，在真机上测性能 | |
| 第 9 周 | **用户签字** | 替换占位模型。M2 结束 |

建模一旦延期，开发可以继续用占位模型往下做。但 **M4 结束前必须换成签字通过的模型**，否则不发布。

## 9. 检查脚本 `scripts/check-model.mjs`（Astra 写）

用 `@gltf-transform/core` 和 `@gltf-transform/extensions` 读取 GLB，检查以下各项。有错误时打印出来，并以退出码 1 结束。

1. `controls.json` 里的每个 id 都有同名节点。
2. 每个活动部件节点都有 `extras`：`kind` 在规定取值内；`axis` 是单位向量；`positions` 的键名和 `controls.json` 的 `positions` 完全一致。
3. 存在 `lcd_screen` 节点，UV 范围是 0–1。存在 `decal_brand` 节点。
4. 包围盒尺寸和规格页的外形尺寸（写在脚本的常量里）相差 ≤ 0.5 mm。
5. 三角面数、贴图尺寸和数量、文件大小在 §7 的预算之内。
6. 打印统计信息：节点数、三角面数、贴图列表、文件大小。
